## The decision rule (pre-registered, stated before the numbers)

Pre-registered before any episode ran (ARCHITECTURE.md §8, "changing any of
this after runs exist is p-hacking"):

1. A task **passes** for an arm iff **≥2/3 seeds** pass — **≥3/5** for tasks
   re-run under escalation. `budget_kill` and `context_exhausted` count as
   failures for every arm; an `error` is re-run once and a second one stands.
2. **Success rate** = tasks passed / N. **Margin** = RLM's passed tasks minus
   the baseline's.
3. The **S4 gate passes iff the margin is ≥ +3 against ALL of B1, B2 and B3**.
   **A tie fails.** A tie-or-loss to **B2** additionally triggers the
   **pivot-to-B2** rule; a tie-or-loss to **B3** records a **pivot-to-RAG**
   finding of the same standing.
4. Every margin is reported beside an exact two-sided **sign (McNemar) test**
   over the discordant tasks and a **10,000-resample paired bootstrap CI** on
   the mean per-task fractional delta.
5. A margin landing in **{+1, +2, +3}** owes seeds **{4, 5}** on that pair's
   **discordant tasks only**; those tasks are re-decided at ≥3/5, the sign
   test and bootstrap are recomputed **once**, and both pre- and
   post-escalation figures are reported. No other recomputation is permitted.
6. Per-category results are **tabled, never gated** — §8 refuses per-category
   margin gates outright. The one per-category rule is the **zero-floor
   tripwire**: a category where RLM scores 0 while any baseline scores ≥3 of
   its tasks blocks the wording "clean pass" and names a mandatory
   category-regression finding, without touching the aggregate gate.
7. Any win claim states its **cost multiple** next to the margin.

## Findings (hand-written, 2026-08-18)

### The headline is real, and it is narrower than "RLM wins"

The gate passed under rules pre-registered before a single episode ran, on a
clean run: **360/360 cells, zero `error` outcomes, zero reruns, zero
budget kills, zero contamination hits.** Every failing cell failed as
`checker_failed` — every arm read its corpus, produced an answer, and was
scored on it. Nothing was rigged, softened, or recomputed.

**But the RLM arm never called the leaf. Not once, in 90 episodes.**
470 `repl_exec` steps, 90 `final` steps, **0 `llm_call` steps.** The
`llm_query` delegation path — the recursion that makes this a *Recursive*
Language Model — was not exercised by a single scored episode.

So the honest claim this run supports is:

> A root LLM with a sandboxed REPL and a deterministic scaffold beats
> single-shot 256K long context, BM25-RAG, and deterministic map-reduce on
> this 30-task benchmark — decisively, and at **lower** cost — **without
> ever delegating to a sub-model.**

It does **not** support "recursive language models beat these baselines."
That claim still has no evidence, after S1, S2, and now S4.

### What the root actually did

From `agg-04` (one of the four aggregation tasks authored so that no regex
scores above chance): the root printed the corpus shape, wrote a regex that
*parses* records into `(id, header_org, status, from_org, to_org)` tuples,
normalised the org strings (catching a leading-article mismatch on its own
second attempt), performed the **header↔disposition join** in Python,
partitioned 1,323 records into 594 WITHHELD / 729 RELEASED / 0 OTHER, and
then **cross-checked its own count by a second method** before answering.

That is the thesis working exactly as §2 writes it — "the LLM's only powers
are writing code that runs in a sandboxed REPL and requesting sub-calls" —
using the first power and never needing the second. The benchmark's
regex-defeating design held: no regex alone solves that task. It was
defeated by a *program*, which is what the category was built to reward.

### Three consequences the project must absorb

**1. §2's cost corollary is falsified — in the opposite direction.** v0.3.1
rewrote §2 to predict the RLM arm would be *slower* than B1 (~1,180 s vs
~624 s on a 200K corpus) and would have to win on "quality-at-a-known-cost,
not speed". Measured: RLM is **0.78× B1's wall-clock, 0.10× B2's, 0.43×
B3's**, at 0.19×/0.06×/0.13× the tokens and 0.41×/0.06×/0.23× the energy.
The prediction was wrong because the mechanism was different: REPL execution
is nearly free next to LLM prefill, and the arm that never prefills a chunk
never pays for one. **The scaffold won on quality *and* cost — because it
skipped the expensive half of its own architecture.**

**2. Every leaf-side finding sat out the result.** R13 (cross-slot
contamination), R14 (concurrent dispatch corrupting answers), the ~1,000-token
distance cliff, the window 640 / stride 480 geometry, the leaf prompt
registry, the leaf's 95% false-positive rate — none of it touched a scored
RLM episode. Those findings remain true and hard-won; they describe a path
the winning arm did not take. The B1/B2/B3 arms exercised the leaf heavily
(16,158 leaf calls, 0 detector hits), so the serving layer *was* measured —
just not underneath RLM.

**3. The claim about B1 must stay narrow.** B1 scored **0/30 tasks** while
answering all 90 times (never once erroring or hitting a budget). That is
consistent with S2's measured distance cliff — this leaf effectively sees
~1,000 tokens around the question — so the supportable sentence is "the
scaffold beats a model that cannot use its own long context on this
hardware", not "the scaffold beats long context". B3's 1/30 says the same
about naive retrieval over these corpora.

### What B2 earned, and what it cost

B2 — the honest control — took **17/30**, tied RLM **8/8 on synthesis**, and
took 4/7 on code QA. Its entire deficit is aggregation (0/7) and the needle
tasks (5/8). Read plainly: **where per-document summarisation suffices, the
scaffold's agency earns nothing**, and B2 pays 7.5× RLM's wall-clock and 16×
its tokens to reach that tie. The pivot-to-B2 rule did not fire, but the
category table says precisely where B2 would have been the cheaper right
answer if the benchmark had been only synthesis.

### Limits of this result, stated rather than implied

- **Corpus shape flatters code.** Aggregation, needle, and synthesis corpora
  are synthetic and *structured* (`[ENT-nnnnn]` markers, `Status:` lines,
  labelled dispositions) — the shape a parser eats. Code QA used real repos
  pinned at fixed commits and RLM still went 7/7, which is the strongest
  single piece of evidence against "it only works on synthetic data", but it
  is 7 tasks.
- **One root model, one box, one benchmark version.** N=30, three seeds,
  `v1`, Qwen3.8-27B root on this hardware.
- **`checked_clean` is evidence, not a certificate.** 15,981 clean leaf calls
  bound contamination low; they do not prove zero. 87 B2 calls are
  `not_checked` and are reported as such.
- **The breach-precedence asymmetry favours RLM** (ARCHITECTURE.md §9 S4): a
  baseline can lose an earned success to a post-answer breach where RLM's
  accepted final outranks a later breach. No cell in this run was decided by
  it (zero budget kills), so it did not touch any margin — but it is named
  here because the verdict promised to name it.

### The one thing to do next

**Price the delegation path, or stop calling this an RLM runtime.** Two ways,
both cheap relative to what they'd settle:

1. **Author tasks code cannot solve** — semantic judgment over unstructured
   prose, where no parse exists and the root must ask the leaf to *read*.
   This is a benchmark-v2 question, and it must be authored before it is run
   (the v1 freeze stands; v1's verdict is what it is).
2. **Run an RLM-variant with the REPL's scan powers restricted**, forcing
   delegation on the existing v1 tasks, and compare. That prices what the
   leaf adds — or shows it subtracts — on tasks whose answers we already
   know.

Until one of those runs, the project's own summary of itself should be
"deterministic scaffold + root-as-programmer, measured", not "recursive
language model, validated".

### Strategic note for `DIRECTION.md`

The product implication is uncomfortable and should be faced early: **if the
win needs no leaf, the two-resident planner+worker topology — the serving
co-design that S0 measured and that DIRECTION.md names as differentiator #1 —
is not load-bearing for this result.** A single resident root plus a REPL
would have produced the same 30/30 at lower memory cost. That does not
invalidate the co-design work (the baselines needed the leaf, and delegation
is still unmeasured), but it means the appliance's minimum viable shape may
be smaller and cheaper than planned, and the library's admission-control
value proposition rests on workloads this benchmark did not produce. Revisit
after the delegation measurement above.
