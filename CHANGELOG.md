- **v0.3.7 — 2026-08-14. R3's prefix-drift detector now EXISTS in production — §7 #3's gate (a1) had no running code path at all.** A survey of what remains in S2 found that `rlm/dispatcher.py` measured `target.prefix_tokens` once per target lifetime and only *stored* it: nothing was ever compared to a pinned value, and **nothing anywhere computed `sha256(rendered_head)`** — so a prefix that moved mid-episode was invisible, and gate (a1) could not have been scored as written. Now implemented: `DispatchTarget.prefix_sha256` is pinned on the first render and **compared on every call**, with a mismatch raising the new `PrefixDrift` (`rlm/errors.py`) — recorded as an ERROR step, **never retried** (drawing again cannot un-change a prefix), and stamped onto every step beside `prefix_tokens`. Four tests added; 501 pass. **Two deliberate deviations from the gate's literal wording, both stated rather than silently taken.** (i) The gate says assert `len(tokenize(head, add_special=True)) == 311` *on every call*; the implementation pins that length once and asserts the **hash** every call instead. The head is byte-identical by construction, so a matching hash implies a matching token count under a target's fixed tokenizer — while re-tokenizing per call would add one `/tokenize` round trip per leaf call, up to `max_subcalls` (926) per episode, to re-derive a number the hash already fixes. The hash is also the *stronger* half: two different prefixes of equal length compare equal on length alone. (ii) The gate says match against `config_snapshot.prefix_render_sha256`; that field is **not** added, because `config_snapshot` is written at episode open, before any leaf call has rendered anything, and the existing code deliberately measures the head from a **real** request rather than a synthetic `[system, user=""]` probe ("the head measured is the head that was actually sent") — a probe that rendered even slightly differently would raise drift on every subsequent call. The per-call assertion subsumes the snapshot comparison and is strictly stronger; every step carries the hash, so a gate runner asserts it is constant across the episode. **The 311 figure is confirmed current and was never in doubt:** it is the RENDERED head, `head_tokens == 311` on 394/394 recorded rows, while the 304/305 the recent probes print is the raw prefix *body* (`prefix_body_tokens == 305` on 394/394) — a different string, not a drifted one.
